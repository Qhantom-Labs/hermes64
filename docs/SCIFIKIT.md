# SCIFIKIT: sci-fi / space styles and the station / tech / ship / alien / terrain / sky kits

The kit adds two style profiles in the Ocarina-era N64 look, and six deterministic kit families that interlock on a
station grid and a terrain grid. Like the forest, polar and dungeon worlds, it is built only from code: painted
textures, baked vertex light and AO, and GLB validation. The designs are original. No franchise assets, names,
logos, ships or silhouettes were used.

- **`space_station`:** clean white hull plating, steel trims and hex decks, cyan light bands, amber hazard frames,
  and dark windows onto star fields.
- **`alien_world`:** a violet-to-peach dusk sky with a ringed planet, ochre regolith, cyan crystals, coral-capped
  stalk trees and glow bulbs, hazy mesas.

Results, real outputs and what is not verified are in `docs/SCIFIKIT-RESULT.md`. Hub and catalog entries for the
merge lane are in `docs/SCIFIKIT-HUB-ENTRIES.md`.

## 2. Style profiles

Both kit packs carry 31 palette colours and **all 59 core material roles**, so every existing kit and character
builds in them. The sci-fi pieces use the role names below, and a role is the only way a piece gets a colour (the
role audit is clean; the known-bad control proves an off-role colour is caught).

### `space_station`

- **Palette groups:** void 1, space 3, hull 6, steel 4, deck 2, neon 4, amber 4, red 2, planet 3, green 2.
- **Key roles:**
  - `wall` / `door`: hull-white plating. Walls use tall enamel panels (two columns, one row), an inset seam, a top light and a hull_4 body; doors keep three rows.
  - `floor`: light steel hexplate. `ceiling`: steel and hull plating. `trim` / `metal` / `frame` / `rail`: steel.
  - `light` / `flower` / `ice`: the cyan light strip and cyan glows. `band` / `hull_alt`: amber hazard stripes and
    trim. `fire`: amber. `screen`: console screens. `glass`.
  - `view` / `vista` / `vista_far`: the star field, nebula and planet painted on view planes.
  - `hull` / `body`: ships, in the hull-white ramp.
- **Light ramp** space_1→hull_4. **Fog** space_2 (deep blue), 10–34 m, inside and out.
- **Look profiles:**

  | profile | purpose |
  |---|---|
  | `corridor` | the default interior |
  | `deck` | quarters |
  | `bridge` | wider fill |
  | `airlock` | cooler key |
  | `hangar` | longer fog |
  | `alert` | variant: amber ambient, hull key, red fill 0.26, deep-space fog kept (red fog drifted magenta, off the palette) |

  `station` / `interior` / `exterior` are aliases.
- **Grade:** contrast 1.08, saturation 0.94, gamma 1.15, exposure 1.16. The runtime applies `pow(c, 1/gamma)`, so
  gamma > 1 lifts mid-tones.
- **Emitters** (`look.emitters`: baked pools and small halos within the convention caps): console and terminal
  screens, the holo pedestal globe, the reactor core, cryo pods, charge pods and the lift. The cyan strips are
  emissive `light` material, not lights.
- **Windows** show the painted star field (`skyx.starfield` as `look.backdrop` behind the view planes, plus
  `stn.viewport` view planes). There is no real sky or space simulation.

### `alien_world`

- **Palette groups:** void 1, sky 6, soil 5, rock 4, cry 4, flo 3, bloom 2, spore 1, gear 5.
- **Key roles:**
  - `sky`: a painted dome with a violet zenith, an aurora band, a rose cloud bank and a pale peach horizon glow.
  - `sand` / `dirt` / `field` / `path`: regolith ramps. `rock` / `stone` / `cliff`: strata.
  - `light` / `ice` / `water`: crystal cyan. `cap` / `flower`: coral caps. `foliage` / `grass` / `bark`: teal stalks
    and fronds. `particle`: spores.
  - `hull` / `body` / `wall` / `door`: lifted light painted gear for ships and outposts.
- **Emitters:** glow bulbs, crystals, the geode, the landing pad lights, charge pods and terminals.
- **Light ramp** rock_1→sky_5, then a near-white **full-bright step** `gear_3`. `bake.FULLBRIGHT_KINDS` (emissive,
  view_plane, card_alpha) take the last step, which keeps crystal glows cyan instead of tinting them peach-green.
- **Fog:** sky_5, 8–48 m, which **is the horizon glow colour**: fog-to-horizon measured 0.03–0.04 against a 0.04 max.
  `view_fog_scale` is 0.5, so the horizon ring and sky bodies sink into the glow (aerial perspective).
- **Look profiles:**

  | profile | purpose |
  |---|---|
  | `surface` | the dusk exterior |
  | `dust` | variant: the horizon glow pulled to 6–34 m, for storm-front regions |
  | `outpost` | interior: rock fog, warm key |

  `exterior` / `dusk` / `interior` are aliases. A `night` variant was tried and **failed the exterior gate**, so it
  was removed rather than loosening anything (CRITIQUE-5).

### Gate thresholds (`view.json` `style_gate`)

These are core defaults (`style_gate.CORE_DEFAULTS`) or stricter everywhere:
- palette adherence ≥ 0.90 (core 0.88);
- black point ≤ 0.14 (0.16);
- mean luma ≤ 0.66 (0.70);
- fog swallowed ≤ 0.20 (0.22);
- exterior void ≤ 0.30 (0.45);
- accent saturation ≥ 0.45 (0.25);
- accent present in ≥ 50% of rooms (core 0);
- station accent fraction ≤ 0.12 (0.15).

The accent **hues** are re-targeted to the genre's accents: cyan 180–200° plus amber 25–50° on the station, crystal
cyan 165–195° plus spore 60–80° on the planet. The core default is a single warm 8–62° band. The n64_fidelity
thresholds come from `kits/core/n64_look.json` and are unchanged. `tests/test_n64_conventions` passes for both
packs.

## 3. Kit families

All generators are deterministic (seeded; two independent library builds give identical bytes). Their textures are
painted by code, vertex AO is baked, every build passes the GLB validator, and budgets are per class:
- sky 128;
- prop 150;
- flora / furniture / arch 300;
- furniture_large 400;
- structure / vehicle 500;
- terrain 512;
- shell 1,500.

The cuboid gate holds each structural piece at ≤ 50% plain boxes.

## 4. Grids and interlocking

- **STATION GRID.**
  - 4 m cells; a room plot is cells × 4 m plus a 0.5 m apron on each side, and door positions sit at
    `4·i + 2` along a side.
  - Corridors are 3.0 m clear and 3.2 m high. Rooms are 4.0 m high. Doorways are 2.0 × 2.6 m.
  - Pieces anchor on `cell_block_centre`, `cell_centre`, `cell_edge`, `door_anchor` (room.gd's door anchor, 0.6 m
    behind the inner face), `wall_face`, `free` or `viewer`. Yaw comes in 90° steps.
- **TERRAIN GRID.**
  - 8 m tiles. Each tile is a closed heightfield slab with typed edges: ground at level 0, 2 or 6 m; ramp a→b on a
    smoothstep; cliff; and a 2.4 m trail band.
  - Inner detail fades to the edge profile over the outer 1.6 m, so neighbours meet without steps. Edges are
    declared in each build's meta (`edges`).
- **Socket manifest** (`kits/library/scifikit-sockets.json`): 114 pieces, plus these connector rules:
  - facing corridor sockets on one cell edge;
  - a door socket takes exactly one `stn.doorway` (room.gd places it through the `arch.door` binding), and an
    airlock may add its leaves as an insert;
  - a window cut takes the viewport of its kind;
  - wall-face props sit on wall sockets;
  - terrain edges must match type and level.

## 5. Room compiler: rooms by data (`tools/scifikit_rooms.py`)

A plan names pieces by key and placement: `block`, `cell`, `edge`, `tile`, `door`, `wall` socket, or free `at_m`
(free props only). It also lists the room's doors, characters, landmark and cameras. The compiler snaps every piece,
then refuses the plan unless:
- every door sits on a door socket and every cut door socket carries a door;
- corridor sockets pair up;
- windows carry viewports;
- wall-mounted props sit on wall sockets;
- terrain edges agree between neighbours;
- only `viewer`-anchored sky pieces are scaled;
- the room estimate (kit tris + 760 per person + collision) is at most 6,000.

The output is plain presentation data: `presentation.rooms[id].pieces` with `kit_shell: true` and per-room cameras.
It reaches the plugin through the normal spec path: scaffold → compile → check (proved) → build_assets → open.

## 7. Runtime and core changes

- **`runtime/godot/view/room.gd`:** one hunk, **byte-identical to the DUNGEONKIT lane's** `kit_shell` hunk (from
  `git diff 219c5c4..dungeonkit-lane -- room.gd`). It skips placeholder walls for `presentation.kit_shell` rooms,
  sets `opening_cut` on kit-room doors, and adds the flag-swapped `asset_when_set` presentation pieces (the open
  airlock). `main` lacked it, and kit-shell rooms cannot render without it. It is no-op data for other packs.
- **`kits/core/pipeline.py`:** one import line (`from . import gen_scifikit`).
- **Nothing else shared changed.** The texture fields register additively. Byte-identity: 46 pre-existing
  generators × forest_village/polar_pod give **92/92 sha256 identical** to a `git archive 0f5f361` build
  (`tools/scifikit_identity.py`).

## 9. Known-bad controls (all rejected)

| control | how it is rejected |
|---|---|
| Over-budget piece | `stn.room` shell stacked ×3 gives 2,664 > 1,500 kit tris (validator). A hangar plan with 2 ships and 8 reactors estimates 7,016 > 6,000 room tris (compiler). |
| Cuboid-only structure | `stn.corridor` with each part replaced by its bounding box gives 100% plain boxes (gate max 50%). The real corridor measures 0%. |
| Palette outside roles | A raw `#ff00ff` in a ramp, and a palette colour no role uses; both are caught by the role audit. |
| Non-interlocking piece | Six cases: a door without a socket, a cut socket without a door, an open corridor end, a grid piece at free metres, a 45° yaw, and a ridge/ground terrain edge mismatch. |
| Holo glow past the rules | A halo of 3.5 m / 1.0 (caps 1.2 m / 0.85) and an emission of 0.60 (cap 0.15) fail the N64 convention check; the shipped views are clean. |

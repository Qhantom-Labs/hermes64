# Contract changelog

## 1.1.0

Additive wave-1b contract, published before implementation: first-class monotone identity collectibles/groups, derived follower flags/count predicates, collection/recall actions, exact symbolic ROBDD fixed-point analysis alongside the concrete oracle, collectible reachability/permanent-loss/threshold obligations, collected-ID save migration, optional suit/coat/dialogue params and authored role-linked node text. 1.0.0 behavior and Last Light remain regression fixtures; original contract documents are archived in `v1.0.0/`. Resource exhaustion is inconclusive, never optimistic abstraction.

### Explicit pre-handoff 1.1.0 amendment (shared core/theme addendum)

Relax `Suit.hood` from the polar-only literal to any nonempty theme-authored string. This is additive: existing 1.1.0 documents retain their meaning; Thaw still requires `silver_faceless` in its own cast tests/data. Cast and room-kit presets live in `packs/polar_pod/presets.json`; no theme constant remains in the core validator. No wire field, action, hash algorithm or 1.0.0 behavior changes. Consumers must render the authored hood value rather than assume the polar theme globally.

## 1.0.0

Initial frozen JSON source/runtime contract: finite Boolean/inventory/dialogue/tide model, reciprocal grid doors, canonical hashes, dependency-scoped room bundles, E1/E2/E3 operations and provenance-bound save migration. Published before implementation. Consumer readiness and verified limitations are in ../CHECKPOINT.md.

# DUNGEONKIT: stone dungeon style and the dungeon / prop / cave / temple / lake kits

The lane adds one style profile, `stone_dungeon`, plus a lit-torch variant, `stone_dungeon_torchlit`. It also adds
five kit families that snap to a documented grid. A room compiler turns room data into plugin rooms, using only
these pieces. The look target is a 1998-era cartridge dungeon: low-poly walls, painted texture courses, per-vertex
light with warm torch pools, soft filtering and tight dark fog.

Everything is original. The textures, meshes, motifs, names and code were made here, and nothing comes from any
shipped game.

Results, measurements and the NOT-verified list are in `docs/DUNGEONKIT-RESULT.md`. The critique rounds are in
`docs/dungeonkit/CRITIQUE-*.md`.

## 2. Style profile `stone_dungeon` (+ `stone_dungeon_torchlit`)

**Palette roles.** There are 32 colours, and every colour belongs to exactly one role. The audit is
`dungeonkit_library.role_audit`, and a test enforces it. Raw hex colours outside the palette are refused.

| role | colours |
|---|---|
| shadow_indigo | void `#06070f`, shadow_0 `#0e1429`, shadow_1 `#172139`, shadow_2 `#27344f` |
| cut_stone | stone_0 `#383a42` … stone_5 `#d9cfbd` (six steps, warm grey) |
| mossy_stone | moss_0 `#26321d` … moss_3 `#828f47` |
| wet_stone | wet_0 `#28303d`, wet_1 `#41505f` |
| torchlight_amber | amber_0 `#5c2913`, amber_1 `#a34b19`, amber_2 `#e28c2d`, amber_3 `#ffcb6a` |
| rune_accent | rune_0 `#1c5958`, rune_1 `#39a296`, rune_2 `#90e2cd` |
| iron | iron_0 `#353a45`, iron_1 `#5b6170` |
| water | water_0 `#0e293a`, water_1 `#1e4e62`, water_2 `#3f8796` |
| timber, cloth | wood_0..2, cloth_0 (chests, crates, banners) |

**Variants share the palette, materials and presets. They differ only in light.**

- The cold `stone_dungeon` bakes a cool ramp `wet_0 → stone_5` (ambient 0.50, key 0.44, AO 0.28).
- `stone_dungeon_torchlit` adds `light_rig.point_bake: 0.5`. Each generator's `meta["bake_lights"]` (sconces,
  braziers, the room shells' torch sockets) is baked into vertex colour as warm pools. These are the only
  surfaces that reach the ramp's top step, `amber_3`.
- `fullbright_back: 1` keeps full-bright roles (sky, flames, runes) one step below that amber top, so they don't
  all turn orange.
- Unlit surfaces top out at stone_5 (0.47 + 0.34 + 0.10 < 5.5 / 6).

**Look profiles** are in `view.json` `look.profiles`, per room via `presentation.look_profile`. N64 dungeons set
light per room, and so does this pack.

| profile | use | key settings |
|---|---|---|
| `dungeon` | halls | Warm-grey ambient 0.55 (0.56 torchlit) and a stone-white key from above. `shadow_2` fog at 9–30 m, max 0.92. Exposure 1.2. Vaults dim from 3.2 m (`room.top_dark` 0.16). |
| `passage` | 3 m corridors | Same rig, and ambient/key stay inside the `n64_look.json` environment ranges. The lift comes from the room grade (exposure +0.14), `floor_lift` 0.45 and a gentler vault falloff. All grazing walls under a top-down key would otherwise read mean luma 0.10–0.12. |
| `cave` | caves | Mossy ground bounce, closer fog (7–24 m). |
| `lakeside` | dusk exterior | Low amber sun. The warm-grey haze is the sky's horizon band (fog tinted to the horizon, 11–44 m). |
| `underwater` | below the lake | Everything sinks into a teal fog at 4–16 m, the classic underwater trick. |

**Ceiling and void handling.**

- Kit rooms are one-sided inward shells. The runtime's N64 cutaway sees through the near walls.
- Kit ceilings (`dgn.ceiling` flat/groin/vault) are separate pieces in sooty dark-stone ramps. A blue vault
  would sit inside the fog colour and read as fog.
- The room profile darkens toward the vault (`top_dark`).
- Doorway sleeves and corridor ends close on a `"dark"` card in the void colour, so they never show uncovered
  background.
- Kit rooms set `presentation.kit_shell: true`, so `room.gd` skips its placeholder walls and window.

**Emitters, UI, audio.**

- `view.json` `look.emitters` give the runtime point light, a painted floor pool and a small halo. The fire
  emitters are sconce, brazier and altar; the rune-glow emitters are crystal, tablet, switch and obelisk. The halo is stone-white, not amber: an additive amber halo over cool stone goes magenta.
- UI: dark-indigo panels, warm-stone text, a torchlight-amber accent. Keyboard prompts only, no text bubbles.
- Audio pointers reuse existing stock sounds (`view.json` `audio`): cave drip, fire crackle, water steps, night
  insects at the lakeside, and `ui.select`. The style pack's `sound_palette` carries ambient + interact.

**Gate thresholds** (`view.json` `style_gate`) were calibrated in the real Godot runtime. Every numeric threshold
equals the core default or is stricter, except two measured, documented deviations:

- `white_point_min` 0.52. The palette has no pure white by design, so a frame's brightest 0.5% are torch flames.
- `contrast_range_min` 0.38. Polar uses 0.40.

The accent family is re-targeted to saturated torch amber (hue 15–55, sat ≥ 0.45). `tests/test_dungeonkit.py`
pins this: any other loosening fails.

## 3. Kit families (all deterministic, validator-clean, recolourable by role)

Every family has 8–12 generators. Each `id__preset` row below is a library build in both variants.

| family | generators (presets) |
|---|---|
| **dgn** (12): dungeon architecture | `dgn.room`: small 2×2, medium 3×3, large 4×3, plus entry, hub, antechamber, shrine, pit, boss_hall. `dgn.corridor`: straight, straight_torch, corner, tee, cross, end_wall, end_wall_torch, end_door, end_door_torch. `dgn.doorway`: frame, arch. `dgn.door_locked`: locked / locked_open, gate / gate_open. `dgn.stairs`: up / down. `dgn.pillar`: square, round, broken. `dgn.wall`: solid, door, slit (window slit), alcove, relief, torch, end_piers. `dgn.pit`: edge, corner, full. `dgn.bridge`: one, two. `dgn.ceiling`: flat / groin / vault in 2×2…4×3. `dgn.floor`: plain, border, cracked, grate. `dgn.rubble`. |
| **dprop** (12): dungeon props | `dprop.sconce` (cage, unlit), `dprop.brazier` (tall, unlit), `dprop.chest` (open, large, large_open), `dprop.breakable` (urn = pot, crates), `dprop.switch` (plinth, lever), `dprop.plate` (pressure plate, down), `dprop.block` (pushable block, eye: a bevelled carved stone with rounded corners and an inset panel, **not** a cube; the cuboid gate checks it), `dprop.statue` (shield), `dprop.banner` (point), `dprop.cobweb`, `dprop.tablet` (rune tablet), `dprop.crystal` (tall). |
| **cave** (8) | `cave.wall` (corner): organic rock walls lofted through warped rounded rings, straight → quarter arc → straight. `cave.floor` (puddle) and `cave.ceiling`: height-field sheets. `cave.spike` (stalactite, column). `cave.boulder` (big). `cave.mouth`. `cave.ledge`: the underground ledge. `cave.cliff` (tall): rounded buttress crests. |
| **tmpl** (8): temple | `tmpl.column` (broken): fluted rings. `tmpl.altar` (cold). `tmpl.relief`: painted carved panel. `tmpl.boss_door` (open): sealed and opened states on the doorway anchor. `tmpl.dais` (large). `tmpl.obelisk`. `tmpl.floor` (single): inlaid. `tmpl.wall` (plain). |
| **lake** (8): lake / water | `lake.water` (pond, large, vast, open). `lake.shore` (corner_in, corner_out, land). `lake.dock`. `lake.bridge` (planks): a boat-less crossing. `lake.reeds`. `lake.lilies`. `lake.waterfall`: falling plane plus foam. `lake.bed`: the underwater floor. The fog tint is the `underwater` look profile. |

**Textures are painted by code.** Large ashlar courses, Voronoi flagstones and warped-Worley cave stone each sit
on exact palette ramp steps, which keeps high-frequency noise low. The doorway relief motif is an arched threshold
with a keyhole, an original design.

**Vertex AO** is baked by `kits/core/bake.py`. There is ray occlusion (`ao_occlusion`, `ao_reach`), height AO and
optional warm point pools. Every build passes the kit validators (budget, naming, origin/scale, palette,
topology) and the DUNGEONKIT gates: cuboid share, the lake water bounds and socket sanity.

## 4. The DUNGEON GRID (interlocking)

- **Cell 4 m.** Walls are inset 0.5 m, so a room plot is cells × 4 m plus a 0.5 m apron.
- **Storey 4.5 m.** Cave storeys are 5.0 m.
- **Corridors** have 3 m clear width. **Doorways** are 2 × 3 m, arched; the cut is 2.8 × 3.6 m.
- **The door anchor** sits 0.4 m in from the room edge, at the side midpoint (`door.position` for side cell i is
  4·i + 2). This is `room.gd`'s own door convention, so plugin doors land on the kit cut.
- **Origins.**
  - Cell-block pieces: at the block centre, on the floor.
  - Cell pieces: at the cell centre.
  - Walls: on the boundary line.
  - Doors and boss doors: on the door anchor.
  - Water: centred.
- **Up is glTF +Y and front is +Z (south).** Grid pieces turn in 90° steps. Free props turn freely.
- **Sockets** are in each build's `meta["sockets"]` and the manifest `kits/library/dungeonkit-sockets.json`. That
  file covers 139 pieces and lists `type`, position, facing, side and cell.
- **Connector rules,** also in the manifest:
  - corridor ↔ corridor: facing sockets on the same cell edge.
  - door → exactly one `dgn.doorway`, optionally with a `dgn.door_locked` / `tmpl.boss_door` insert.
  - torch → `dprop.sconce`.
  - wall → `dprop.banner` / `tmpl.relief`.
  - pit → `dgn.bridge`, running north–south.
  - shore → `lake.water` at the water level.
  - cave edge ↔ cave edge.

## 5. Room compiler: rooms by data

`tools/dungeonkit_rooms.compile_room(plan)` turns a room plan into a normal plugin room plus its `presentation`
row:

- `pieces`, each `{asset, position, yaw, kind}`, or state-swapped `{asset, flag, asset_when_set}`
- `look_profile`
- `kit_shell`
- cameras

A plan has these parts:

- `plot_cells`.
- `pieces`, each placed by `block` / `cell` / `edge` / `corner` / `at_m` / `socket`.
- `wall` mounts on sockets.
- `props`.
- `doors`: side + cell.
- `characters`.
- `cameras`.

It refuses, with `PlanError`, anything that does not interlock:

- a key that is not a DUNGEONKIT piece
- a grid piece placed at free metres
- a grid piece at a non-90° yaw
- a door with no door socket, or a cut door socket with no door
- a corridor socket that meets nothing
- an open room cell (pit/stairs) with no fill piece
- a wall mount without its socket
- a grid piece used as a free prop
- a room over the 6,000-triangle cap: kit tris plus 760 per person

**Locked doors and the boss door are state-swapped pieces.** `room.gd` shows `asset` until the story flag is set,
then shows `asset_when_set`. The demo uses `gate_open` and `boss_door_open`.

The demo (`tools/dungeonkit_demo.py`) goes through the plugin's ordinary path: story spec → compiler/validation →
modules (checkpoints, regions) → presentation → Godot `room.gd` / `rig.gd`. It has a lakeside, a gatehall, a
corridor, a pit hall, a key vault, the boss-door hall and the sanctum. `write` / `check` / `plan` / `capture` are
its commands.

## 6. Lake kit across every style profile

The lake generators ask only for roles that every kit pack defines: water, sand, path, grass, rock, cliff, wood,
post, rope, foliage, flower and snow. A palette swap is therefore a pack swap.

- `kits/library/dungeonkit-xprofile/` holds the same 8 generators built with `polar_pod` and `forest_village`.
- The city lane's `city_district` / `city_district_night` packs build cleanly too. That was a scratch,
  read-only run, because those packs are not on this branch.
- The sheet is `docs/dungeonkit/lake-xprofile-sheet.png`.

**The water shader** is N64-style: a UV scroll plus a per-vertex sine swell in world space, so tiles stay
continuous. That is the `wobble` uniform in `n64_world.gdshader`, fed from `extras.n64.wobble` by
`view/assets.gd`.

The lake gate bounds it at wobble ≤ 0.08 m, wavelength ≥ 2 m, speed ≤ 2.5, and surface scroll ≤ 0.06 UV/s. Falling
water may scroll at ≤ 0.8 UV/s with no wobble. The schema ranges refuse more at resolve time, and the gate refuses
a tampered GLB.

## 7. Runtime changes (small, additive)

- `runtime/godot/shaders/n64_world.gdshader` adds `uniform vec4 wobble` (x amplitude, y wavelength, z speed). It
  is a no-op at 0.
- `runtime/godot/view/assets.gd` sets `wobble` when a material's `extras.n64` carries it: one line.
- `runtime/godot/view/room.gd` adds three things:
  - `presentation.kit_shell` skips the placeholder walls and window.
  - Flag-swapped presentation pieces (`flag` / `asset_when_set`).
  - Placed pieces get `placed` kind meta and `mounted` meta.

## 8. Core kit changes: opt-in, byte-identical elsewhere

`kits/core/bake.py` changes, each keyed on pack data:

- `asset_rig`: a per-asset light rig.
- `light_rig.point_bake` + `meta["bake_lights"]`.
- `ao_occlusion` / `ao_reach`: ray AO.
- `fullbright_back`.

`kits/core/pybuild.py` changes:

- Per-role `material_extras` (`scroll` / `wobble` / `alpha`) go into `extras.n64`.
- It uses `bake.asset_rig`, and so does `assemble.py`.

A pack without these keys exports byte-identical GLBs. A sweep of all 46 pre-existing generators × forest/polar
gave 92/92 identical sha256 against `main` 219c5c4. `tests/test_dungeonkit.py` pins seven of those hashes.

## 9. Tools

```sh
PY="env PYTHONDONTWRITEBYTECODE=1 python3 -B"
$PY -m tools.dungeonkit_packs write|check        # kit packs (palette roles, materials, rig, presets)
$PY -m tools.dungeonkit_style write|check        # style packs (look profiles, emitters, UI, audio, gate)
$PY -m tools.dungeonkit_library all              # build + validate + gate + sRGB8 + manifest + bindings + sockets + xprofile
$PY -m tools.dungeonkit_library verify           # hashes, bindings, gates
$PY -m tools.dungeonkit_library sheet|xsheet     # real-renderer QA sheets (per kit / lake across profiles)
$PY -m tools.dungeonkit_demo write|check|plan    # demo spec via the room compiler
$PY -m tools.dungeonkit_demo capture --round N --variant stone_dungeon_torchlit --view a|b|c|d   # Godot capture + gates
$PY -m tools.dungeonkit_controls                 # known-bad controls (all must be REJECTED)
$PY -m tools.dungeonkit_moods paint|check        # mood images -> refpack -> compare (docs/dungeonkit/REFPACK-CHECK.md)
$PY -m unittest tests.test_dungeonkit
```

## 10. Known-bad controls

`tools/dungeonkit_controls.py` pushes real artefacts through the shipped validators. Every one is rejected.

| control | rejected by |
|---|---|
| over-budget room shell | The kit budget validator: `dgn.room` stacked three times is 3,924 > 1,500 tris. The room compiler: 8,624 > 6,000. |
| cuboid-only wall | The cuboid gate: 100% boxes > 50%. The real wall is 0%. |
| palette outside roles | The role audit: a raw colour, and a palette colour in no role. |
| non-interlocking piece | `PlanError` in 6 cases: door without socket, cut socket without door, open corridor end, grid piece at free metres, 45° yaw, open pit cell. |
| water that breaks the gate | Schema range (wobble 0.3 > 0.08), and the lake gate on a GLB tampered past the bounds. |

## 11. Plugin tool budget

**No tool was added.** The 27-tool, 6,000-token compact schema is untouched, and `adventure_maker/schemas.py` is
unchanged. The kits come in through existing paths:

- style packs in `packs/`
- `kit_pack_id`
- bindings
- the room/presentation data
- the existing build tools

The merge lane needs no registration lines.

# Frame time (MERGE2)

Generated by `tools/merge2_perf_report.py` from local receipts under `evidence/merge2/opus/` (gitignored). Every number below is read or derived from JSON receipts; nothing is typed by hand.

## Summary

- **Steady frame work is far under the 8 ms target on this M4 Pro.** Frame work (time inside each frame's CPU phases, from timestamp probes; see the cost table) on the exported builds' renderer (GL Compatibility), noise floor of three deterministic repeats: p95 <= 3.08 ms, p99 <= 3.53 ms, max <= 9.33 ms across Reedland Relay, Thaw and Last Light (T7); Metal (editor/dev renderer): p95 <= 0.70, p99 <= 0.96, max <= 6.93 ms.
- **Wall frame time is a different number and is reported next to it.** The wall interval between frames adds GPU execution and present/vsync waits. With vsync off on GL Compatibility its steady p95 is <= 6.0 ms (floors; under the 8 ms target); Metal's is 16.6 ms because Metal paces frames to the display even with vsync off: pacing, not work. GPU time itself is not measured (GPU timestamps read 0 on both macOS drivers).
- **The retained "37 ms rendered p95" was a measurement artifact, not frame cost.** The old gate sampled Godot's `Performance.TIME_PROCESS`, which is the *maximum* over the previous wall second of process + RenderingServer sync/draw/present (drawable and vsync waits included): it changed value 13-32 times in 12-32 wall seconds (T4) and its median is 22.1-47.0 ms while measured per-frame work on the same frames has a median of 0.53-1.22 ms.
- **Real costs were hitches, now fixed without any visual change:** character glTF read and decoded on every spawn (3.2-8.5 ms each before, 0.44-0.49 ms after), every kit file re-hashed on every room build, GPU-readback triangle counting (19.0 ms per call on Metal before; bot instrumentation only), and GL-Compatibility shader compiles when an object first enters the view (6 mid-walk frames over 33.34 ms in 3 runs before, 68-120 ms; 3 after). A full room rebuild is 2.2-2.7x faster (T6); details in T5/T6.
- **Steady cost is unchanged by the fixes.** An interleaved A/B on the same movie (GL Compatibility, Reedland Relay) measured steady frame work p50 0.735 ms before and 0.745 ms after (+0.010 ms, inside run-to-run variation of 0.093 ms; see T7).
- **No visual lever is worth applying.** MSAA 4x->2x/off, nearest upscale, half viewport, hidden UI and a 1x window each change the render-CPU median by at most 0.11 ms (T3). Nothing was changed visually, so there is no look decision to bring to Dylan.
- The official rendered budget stays **33.34 ms p95**. The playtest gate now measures per-frame work from timestamp probes (the old monitor value is still reported as `monitor_*`), and a negative control proves it still fails a genuinely slow game (see "Gate").

## Cost table (final code)

Columns. **Frame work**: wall-clock time inside one frame's CPU phases (physics callbacks, physics step and deferred calls, process callbacks, RenderingServer measured render CPU), from timestamp probes at global SceneTree priorities. It excludes the GPU, present and vsync waits between frames, and equals CPU work when Godot's thread is not preempted. **Wall interval**: start of one frame to the start of the next, vsync off; frame work plus GPU, present and pacing waits, so an upper bound on a frame's cost. **Floor**: per-tick minimum over 3 deterministic replays of the same real-input movie, which removes preemption by other processes on this shared Mac. Steady (this harness) = after each room's first 120 frames (2 s at 60 Hz); warm-up = those first frames (boot shader compile and first room entries).

## Machine and method

- Apple M4 Pro (10 performance + 4 efficiency CPU cores, 20-core GPU), 64 GB, macOS 27.0.1, display 3840 x 2160; Godot 4.6.2-stable (official) (`machine.json`). 1-minute load average from other work on this Mac during these runs: 8-53 on 14 logical CPUs (recorded per run in each `summary.json`).
- Renderers: **GL Compatibility / OpenGL 3** is what `hermes64_export` ships (macOS app and web); **Mobile / Metal** is the project default used by the editor, `godot --path` runs and the playtest bots. Production presentation: 3D in a 320x240 SubViewport with MSAA 4x, shown 3x at 960x720 (canvas_items stretch, linear filter).
- Scenario: one recorded real-input movie per game, replayed by the production presenter at a fixed 60 Hz (`--fixed-fps 60`), vsync off unless stated: Reedland Relay module movie (1,900 ticks, 3 rooms/regions: arena, field, hub), Thaw winning-0 (2,062 ticks, 6 rooms/regions: conversation_pit, curved_corridor, dome_shelter, pod_bay, snow_field, workstation), Last Light winning-0 (791 ticks, 4 rooms/regions: boathouse, fog_street, keepers_cottage, lamp_room). Every run must reproduce the movie's state hashes, so all levers and builds simulated the identical game. "After" runs overlay the current repository code on the same prepared runtime and replay the *same* movies (pinned build hash); the hashes still matched in every run.
- Per-frame phases come from timestamp markers at global SceneTree priorities (-1000/+1000 and between each consumer: Actions -100, presenter -50, player 0, module host 10, actor bridge 12, movie 100). **Frame work = physics callbacks + physics step/deferred calls + process callbacks + RenderingServer measured render CPU.** GPU execution and present/vsync waits are not CPU work; the GL-compat wall interval with vsync off (steady p95 6.0 ms, Reedland floor) bounds them from above. GPU timestamps report 0 on both macOS drivers, so no GPU column is claimed.
- **Steady** (this harness: every table except the rendered-gate tables) = room age > 120 frames, excluding replay-hash frames; warm-up is reported separately. The playtest gate uses room age > 72 frames (`WARMUP_FRAMES` in `playtest/runner.gd`) with harness frames excluded. **Floor** = per-tick minimum over 3 deterministic repeats: preemption under load rarely hits the same tick twice, so spikes that survive the floor are intrinsic.

- Room transitions load each room's kit files on first entry: Thaw transition frames 0.8-16.2 ms after the fix (T6 note). Next step if wanted: preload the game's kit set at boot.
- Metal (dev/editor) frame pacing shows 16.6 ms wall p95 even with vsync off (drawable/compositor), unrelated to work.
- Single rendered runs on this shared Mac can show isolated long frames when other processes preempt Godot. The floors above (minimum per tick over 3 runs) remove such preemption.
